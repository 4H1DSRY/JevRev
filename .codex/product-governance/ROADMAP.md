# JevRev Flagship Roadmap

Last reviewed: 2026-09-22

## Allocation Policy

- Preserve runtime and protocol behavior unless a verified flagship requirement needs a focused change.
- Use existing fixtures and demonstrations before creating a new benchmark subsystem.
- Close documentation contradictions before adding new claims.
- Treat experimental measurements as supporting evidence, not the product explanation.
- Keep the final diff centered on README communication, the supporting asset, and necessary verification.
- Preserve the existing banner, title, tagline, badges, product boundary, and durable section anchors while shortening the reading path.
- Present JevSift, Probe/Decide, and JevLoop as shipped; present JevLong or JevKanban only as a roadmap layer.

## Current Phase P4 Flagship Evidence And Coherence

Objective: make the current Sift, Probe, Evidence, and Decide product understandable through one verified engineering case.

Exit criteria:

- The current product boundary and evidence hierarchy are consistent across README, workflow, acceptance, and release-facing copy.
- A completed mini-project demonstrates a proposal ranking changing after executable evidence.
- README structure and copy are ready before visual production begins.
- README moves directly from tiered positioning to verified proof and low-friction hosted or local setup.
- The visual handoff freezes verified facts, prohibited claims, narrative order, and asset constraints.

## Visual Phase

Objective: create and integrate two complementary proofs without changing experiment facts: the decision-gate SVG and a compact one-shot storefront comparison.

Exit criteria:

- The SVG is accessible, dependency-free, responsive, readable on GitHub light and dark surfaces, and validated after rendering.
- README placement produces a clear top-of-page reading path without duplicating later documentation.
- The temporary text proof is replaced by the verified visual without changing adjacent facts or product positioning.
- The one-shot comparison uses a fixed shared content and behavior contract, records direction-level asset choices, and renders both pages at desktop and mobile sizes.
- The comparison is additive and compact. It does not replace the ranking-reversal proof or push setup and usage out of the top reading path.

## Final Integration Phase

Objective: synchronize with upstream, run proportional verification, inspect the diff, and prepare a reviewable commit.

Exit criteria:

- Relevant tests, demos, build, and package dry run pass.
- No significant upstream change invalidates the case or copy.
- All visible claims remain within the verified evidence boundary.

## Deferred Scope

- Automatic implementation or worktree orchestration.
- A new general-purpose benchmark framework.
- Production defect, developer-hour, or coding-agent token savings.
- Dashboards, JevLong, and long-run monitoring beyond the shipped JevLoop round protocol.
- Remote repository description and topics until final visual integration and copy review are complete.
